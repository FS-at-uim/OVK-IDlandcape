# ADR 0017: Unified Config Portal und Git-basierte Multi-Admin- & Partner-Auth-Registry

- **Status**: Accepted
- **Kontext**: Bislang waren die Editoren in zwei getrennte Werkzeuge unterteilt (`core_editor.html` für DSPs/SSPs/Data Partners und `vermarkter_editor.html` für Vermarkter). Zudem mussten neue Partner-Passwörter manuell über Secrets im Cloudflare-Dashboard (`PWD_*`) hinterlegt werden, was für Administratoren umständlich war. Es gab nur ein globales Master-Admin-Passwort, wodurch mehrere Administratoren keine individuellen E-Mail-Logins hatten. Partner sahen außerdem technischen JavaScript-Code und es fehlte ein eindeutiger Hinweis auf den nächtlichen Veröffentlichungszyklus.
- **Entscheidung**: 
  1. **Gatekeeper Worker Erweiterung**: Der Cloudflare Worker (`docs/gatekeeper_worker.js`) wird um eine Git-basierte Auth-Registry (`config/auth_registry.json`) erweitert. Passwörter werden sicher mit SHA-256 gehasht (unter Verwendung eines 16-Byte Web Crypto Salts und eines Worker-Peppers), sodass Passwörter niemals im Klartext im GitHub-Repository liegen.
  2. **Multi-Admin via E-Mail**: Das System unterstützt mehrere gleichberechtigte Administratoren mit eigener E-Mail-Adresse (`role: 'admin'`). Beim Login kann wahlweise eine E-Mail-Adresse oder eine technische ID eingegeben werden.
  3. **Admin-Endpoints zur Benutzerverwaltung**: Bereitstellung von `POST /admin/save-partner-auth` und `POST /admin/delete-partner-auth`, mit denen Administratoren neue Admin-Accounts und Partner-Logins direkt im Portal anlegen, verwalten und löschen können, ohne Zugriff auf Cloudflare zu benötigen.
  4. **Konsolidiertes Portal (`editor.html`)**: Zusammenführung beider Editoren in ein zentrales Portal im offiziellen `tech.ovk.de` Design (Dark Navy `#010f2d` Header mit OVK-Rot-Akzent, zentrierter 960px Container, kein JS-Code für Partner, kompakter Nacht-Live-Hinweis neben dem Speichern-Button).
  5. **Ergonomische Vermarkter-Matrix & DSP-Ausschlüsse**: Vermarkter pflegen ihre ID-Bereitstellung über eine Coverage-Matrix für 4 Inventargattungen (Desktop, Mobile Web, In-App, CTV) mit Schaltern und Prozentwerten (0–100%). DSP-Ausschlüsse werden über ein Flyout gesteuert mit dem expliziten Hinweis, dass eine DSP nur dann ausgewählt wird, wenn eine Weitergabe der ID durch diese DSP ausdrücklich ausgeschlossen werden soll.
- **Konsequenzen**: 
  - *Vorteile*: Mehrere Administratoren mit individuellen E-Mail-Adressen; volle Benutzerverwaltung ohne Cloudflare-Zugriff; automatische Rollenerkennung beim Login; granulare Berechtigungsabsicherung für alle Partnertypen; kein technischer JS-Code für Partner; aufgeräumte, ergonomische 960px-Oberfläche im Corporate Design von tech.ovk.de.
  - *Nachteile*: Der Cloudflare Worker Code muss einmalig im Cloudflare Dashboard aktualisiert werden (Copy & Paste aus `docs/gatekeeper_worker.js`), damit die neuen Endpoints und E-Mail-Logins im Worker aktiv werden.
